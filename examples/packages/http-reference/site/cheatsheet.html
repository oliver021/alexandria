HTTP status cheat sheet

A one page companion to the tables of the http-reference package. The complete data lives in tables/status_codes.csv.

The five classes

ClassMeaningCodes you will use most
1xx informationalThe request was received and the process continues.100, 101, 103
2xx successThe request was understood and accepted.200, 201, 202, 204
3xx redirectionThe client has to take another step to finish.301, 304, 307, 308
4xx client errorThe request cannot be fulfilled as sent. Repeating it unchanged will not help.400, 401, 403, 404, 409, 422, 429
5xx server errorThe server failed on a valid request. Retrying later may work.500, 502, 503, 504

Choosing a status for an error

  1. Is the credential missing or invalid? Send 401 with WWW-Authenticate.
  2. Is the caller known but not allowed? Send 403, or 404 to hide that the resource exists.
  3. Does the resource not exist? Send 404. If it was removed on purpose, 410.
  4. Is the body unreadable? Send 400. Is it readable but invalid? Send 422.
  5. Does the request clash with the current state? Send 409, or 412 when an If-Match condition failed.
  6. Is the client going too fast? Send 429 with Retry-After.
  7. Did the server fail? Send 500. If an upstream dependency failed, 502 or 504. If it is overloaded, 503.

Methods at a glance

MethodSafeIdempotent
GET, HEAD, OPTIONS, TRACEyesyes
PUT, DELETEnoyes
POST, PATCH, CONNECTnono

Safe means the method does not ask the server to change anything. Idempotent means that sending the same request several times leaves the server in the same state as sending it once.
